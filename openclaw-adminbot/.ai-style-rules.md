# Style rules for this repo

Conventions inferred by reading the tree, not aspirations. Every rule below was checked
against real files; the exemplars are named so you can imitate something concrete rather
than interpret a sentence. Structural decisions live in [docs/adr/](docs/adr/); the map is
[docs/architecture.md](docs/architecture.md); the non-negotiables are in
[AGENTS.md](AGENTS.md).

## Rules

**Naming and files**

- `kebab-case.ts` everywhere. Colocate the test as `x.test.ts` next to `x.ts`.
- Shared test scaffolding is `x.test-helpers.ts` / `x.test-support.ts` / `x.test-harness.ts`.
  Use the **dot** form: `scripts/lib/codemod-move.ts` carries `.test.ts`, `.test-helpers.ts`
  and `.test-support.ts` as sibling suffixes, so a dot-named helper travels automatically
  when its source moves and a dash-named one does not. (25 dash-named helpers predate this —
  see the conflict note at the bottom.)
- Splitting a file produces **dot-suffix siblings**, not a new subdirectory:
  `attempt.ts` → `attempt.session-lock.ts`, `attempt.llm-boundary.ts`. The fragment's docblock
  names the stage it came from.
- Generated files say so in the first line and name their generator
  (`extensions/adminbot/src/workflows/deadlines/generated/dataset.ts` is the model).

**Imports**

- Explicit relative paths with a **`.js` extension** in `src/`, `extensions/`, `packages/`
  and `scripts/` — 34,141 specifiers to 72 exceptions. `ui/src/` is the opposite (`.ts`
  specifiers, Vite-resolved); match the file you are in, not the other tree.
- **No new barrels.** `src/` has exactly 18 `index.ts` files and that number is a decision,
  not an accident: because every import is an explicit path, a barrel both hides the real
  dependency and makes every move rewrite more files. `packages/*` are the deliberate
  exception — a workspace library's `src/index.ts` _is_ its public surface.
- Cross-domain imports inside `src/` are frozen. Adding an edge between two top-level `src/`
  domains means editing `config/layering.json` by hand, which is the point:
  `pnpm check:layering` fails on an unlisted edge ([ADR-0004](docs/adr/0004-agents-is-the-application-layer.md)).
- `extensions/*` reach the core only through `openclaw/plugin-sdk/*`. A new subpath needs
  **three registrations**: `src/plugin-sdk/<name>.ts`, the `./plugin-sdk/<name>` entry in root
  `package.json` exports, and `extensions/tsconfig.package-boundary.paths.json`
  ([ADR-0003](docs/adr/0003-plugin-sdk-stays-flat.md)).

**Where things go**

- New cross-cutting helper → `src/shared/` (its root, or a topical subdirectory like
  `shared/text/`). There is no other correct location. `src/utils.ts` is **frozen**: 227 lines,
  ~300 importers, no new exports and no new importers
  ([ADR-0005](docs/adr/0005-shared-is-the-helper-home.md)).
- Anything with an external effect is a typed action in
  `extensions/adminbot/src/contracts/actions.ts` that goes through
  **propose → approve → execute → audit**. Proposals are produced in `workflows/`, executed in
  `connectors/`, and an action type no connector handles **fails closed**. A `workflows/` module
  that imports a connector is wrong by construction
  ([ADR-0002](docs/adr/0002-adminbot-executors-features-seam.md) for the seam,
  [ADR-0007](docs/adr/0007-adminbot-adopts-the-v2-taxonomy.md) for the names, and the hard rules
  in [AGENTS.md](AGENTS.md)).
- Moving files goes through a manifest: write `scripts/moves/<step>.json` and run
  `scripts/lib/codemod-move.ts`, which does the `git mv`, rewrites relative specifiers across
  `src`, `extensions`, `packages`, `scripts`, `test` and `ui`, and sweeps build/config files
  that name the old paths. One move per commit, so it is invertible.

**Writing the code**

- TypeScript ESM, strict. Prefer real types over `any`; `typescript/no-explicit-any` is on at
  error level everywhere except test files.
- **Comments explain _why_** — an invariant, an ordering constraint, a failure mode, a
  decision someone will otherwise undo. Not what the line does. The openreview executor's
  "the message body goes over stdin, never argv: bodies are multi-line and would otherwise
  show up in the process table on a shared host" is the target register.
- Split around **~700 lines** when it improves clarity. The automated gate is **2,200 lines**
  (`max-lines`, tests exempt); the 39 files over it carry a
  `// oxlint-disable max-lines` header naming
  [ADR-0006](docs/adr/0006-deferred-monster-splits.md) and are grandfathered, not endorsed.
  New code added to one of those files should be extracted, not appended.
- A deferred split is unblocked by **characterization coverage**, not by scheduling. Cut one
  stage at a time behind its own tests.
- American spelling. "AdminBot" in prose, `adminbot` in code and paths.

## Don'ts

- **Never run bare `pnpm test`.** A whole-repo vitest sweep OOM-thrashes this box. Always
  scope: `pnpm test extensions/adminbot`, `pnpm test src/config`. If a lane stops producing
  output it has wedged rather than failed — kill it and re-run per file; the per-file counts
  sum to the same baseline.
- **`pnpm build` is runnable again** (verified twice at ~45s, exit 0, with and without
  `NODE_OPTIONS=--max-old-space-size=4096`) — the historical "builds OOM this box" warning
  predates the build-plan repair. It is still the heaviest command here, so do not run it
  alongside a test lane, and prefer `pnpm tsgo:core` / `pnpm check:changed` for a quick
  signal.
- **Don't fix a known-red baseline in an unrelated commit.** `pnpm lint` is 270 errors,
  `format:check` is 36 files, `tsgo:core` is 15 errors, `test/scripts` has 6 failures. Growth
  in those numbers is a failure; a drive-by improvement makes the comparison unreadable for
  whoever reviews the actual change. Fix them in their own commit, and move the number in
  [docs/refactor-baseline.md](docs/refactor-baseline.md) when you do.
- **Don't hand-edit generated or vendored files.** `*.generated.ts`, `src/state/*.generated.d.ts`,
  `extensions/adminbot/src/workflows/deadlines/generated/dataset.ts`, and
  `src/auto-reply/reply/export-html/template.js` (which `.oxlintrc.json` ignores outright).
  Regenerate instead, or fix the generator.
- **Don't add a code path that reaches Slack, Gmail, Calendar, Overleaf, OpenReview or a
  social network without the approval gate.** Not "temporarily", not behind a flag.
- **Don't treat `ui/src/ui/adminbot/access.ts` as security.** It hides tabs. A new privileged
  route needs a server-side check in the service _and_ a gateway device scope.
- **Don't commit secrets.** `.env`, `client_secret*.json` and `state/` are ignored and stay
  ignored; credentials live in `~/.openclaw/credentials/`.
- **Don't be surprised when `git commit` is blocked.** `git-hooks/pre-commit` formats staged
  files, re-stages them, then lints them. Touching an already-red file blocks on pre-existing
  errors; `git commit --no-verify` is the escape the hook itself documents. Confirm by hand
  that `pnpm lint` did not grow before you use it.

## Known convention conflicts

Two live patterns for the same thing. **Not resolved here** — recorded so nobody "fixes" one
half of a split by mistake.

1. **Import specifier extension.** `src/`, `extensions/`, `packages/` and `scripts/` write
   `.js`; `ui/src/` writes `.ts` (1,429 to 119), and single files mix both —
   `ui/src/ui/navigation.ts` imports `../i18n/index.ts`, `./string-coerce.ts` and
   `./icons.js` in the same header. Follow the surrounding file.
2. **Test-helper file naming.** 124 files use the dot form (`x.test-helpers.ts`); 25 use a
   dash (`src/acp/translator.bridge-test-helpers.ts`,
   `extensions/slack/src/monitor/events/system-event-test-harness.ts`, …). Only the dot form
   is a `siblingSuffixes` entry in `scripts/lib/codemod-move.ts` — and `.test-harness.ts` is
   not in that list at all, in either form, so harnesses do not travel with their source
   under a codemod move.
